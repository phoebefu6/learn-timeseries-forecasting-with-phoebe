Part 1 · covers DeepAR / global-model motivation

Why a deep, global model at all 6 min live

Everything up the ladder so far - ETS, ARIMA, Prophet - fits one model per series. That is fine for Lumen's single daily-sessions line. But when you have thousands of related series (every product, every store, every region), deep models offer something classical methods cannot: a single global model that learns shared patterns across all of them, borrowing strength from short and new series. They also handle long horizons, many exogenous inputs (price, promotions, weather), and produce probabilistic outputs (quantiles), not just a point.

LiveThe four things deep models are actually good at3 min▶

Deep forecasting is not "better ARIMA". It solves a different shape of problem:

  • Many related series. Train once, globally, and every series - including short and brand-new ones - benefits from patterns learned elsewhere.
  • Long horizons. Multi-horizon architectures forecast the whole path at once rather than recursing one step at a time.
  • Exogenous inputs. Known-future covariates (promotions, holidays, price) and static features (category, region) go straight in.
  • Probabilistic output. Quantiles or a full distribution, so the prediction interval is a first-class citizen, not an afterthought.
Real world

Lumen is the wrong-shaped problem - on purpose. One daily-sessions series is exactly where a global deep model has nothing to borrow from. If Lumen grew to forecast every SKU across every market daily, that fleet of related series is when DeepAR or TFT start to pay off. Match the model to the shape of the problem, not to the hype.

Part 2 · covers DeepAR, N-BEATS, TFT

Three landmarks worth knowing 5 min live

Three papers anchor the modern deep-forecasting map. You do not need to implement them tonight - you need to know what each is for, so you can pick the right one (or decide none of them beats your baseline).

ModelWhat it isWhy it matters
DeepAR
Salinas et al. 2020		An autoregressive RNN trained globally across many series, predicting a distribution (e.g. quantiles), not a point.The reference for probabilistic, at-scale forecasting when you have a large panel of related series.
N-BEATS
Oreshkin et al. 2020		A pure deep residual stack of basis-expansion blocks - no RNN, no attention - with an interpretable trend/seasonality variant.Strong accuracy from a simple, fast architecture; the interpretable blocks echo classical decomposition.
TFT
Lim et al. 2021		Temporal Fusion Transformer: attention over past inputs plus known-future covariates, multi-horizon, with built-in interpretability.The go-to when you have rich known-future inputs and want to see which ones the model leans on.
Self-studyThe tooling you would actually reach for2 min read▶

Nobody hand-codes these from scratch for a project. The ecosystem does the heavy lifting:

  • GluonTS - the home of DeepAR and a broad probabilistic-forecasting toolkit.
  • PyTorch-Forecasting - production-friendly TFT, N-BEATS, DeepAR on top of PyTorch Lightning.
  • Darts - a single, sklearn-like API across classical and deep models, easiest for a first sketch.
Baseline first, always Before any of these, you already have the seasonal-naive baseline (b1) and ETS/ARIMA/Prophet (b3-b5). A deep model only earns its complexity if it beats those on a backtest (b8) - not on one lucky holdout.

How a deep model is fed: the sliding-window dataset ★ 12 min · sketch, not a model

You do not train anything here - you build the dataset shape deep models consume. A window of past values becomes the input X, the next H values become the target y, and windows are pooled across many series into one global training set. This numpy sketch runs, but it is here to build intuition, not a forecaster.

Slide a fixed lookback window across a series; each position yields one (past window → next H) training row.

Repeat for many related series and stack the windows into one pool - this is what "global" means.

Inspect the shapes: thousands of rows, each mapping a past window to a multi-step target.

★ Illustrative sketch (Python) - how deep models are fed, NOT trainedimport numpy as np # ILLUSTRATIVE ONLY: this builds the DATASET SHAPE a deep/global model eats. # It trains nothing - it shows how past windows become (X, y) rows, pooled. def make_windows(series, lookback=28, horizon=14): X, y = [], [] for t in range(lookback, len(series) - horizon + 1): X.append(series[t - lookback:t]) # past window -> inputs y.append(series[t:t + horizon]) # next H values -> targets return np.array(X), np.array(y) # pool windows from MANY related series into ONE training set (global model) rng = np.random.default_rng(7) series_bank = [1000 + 3*np.arange(180) + rng.normal(0, 20, 180) for _ in range(50)] # 50 Lumen-like daily series Xs, ys = zip(*(make_windows(s) for s in series_bank)) X = np.concatenate(Xs); y = np.concatenate(ys) print("global training set:", X.shape, "->", y.shape) # (~many, 28) -> (~many, 14)
Real world

This is where leakage sneaks back in. Every window must respect time: X is strictly before y, and when you split for evaluation you split by date, not by shuffling windows. A shuffled window split leaks the future exactly like a shuffled row split (b1) - just harder to spot.

Check yourself

Three questions before you go 🎯 ◐ 90 seconds

1 · What is the main advantage of a global deep model?

Global models learn shared patterns across a whole panel of series. That is their edge - not raw accuracy on one short line, where classical methods usually win.

2 · Which model is built to use known-future covariates with attention, multi-horizon?

TFT (Lim et al. 2021) applies attention over past inputs plus known-future covariates and forecasts multiple horizons at once, with built-in interpretability.

3 · When is a deep model probably the wrong tool?

The M-competitions are blunt: on a single short series, complexity rarely pays. Deep earns its place with many related series, long horizons, and rich inputs.
